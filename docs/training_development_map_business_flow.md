# 培训发展管理地图控件业务流逻辑

本文用业务语言说明两个控件的处理逻辑，不展开底层代码设计。

- 中国区人员服务资质地图
- 中国区培训覆盖地图

## 一、中国区人员服务资质地图

### 1. 这个控件解决什么问题

这个控件用来回答：

- 哪些分公司有多少服务资质？
- 哪些产品线和型号的服务能力覆盖比较好？
- 哪些资质快到期或已经过期？
- 哪些分公司存在资质风险，需要提醒或补齐？

地图上的每一个点，代表一个分公司。

### 2. 用户需要导入什么

用户导入人员服务资质表。表里通常包含：

- 分公司
- 人员姓名
- 单位或经销商
- 产品线
- 机器型号
- 服务资质类型
- 资质有效期
- 区域或大区

系统会把这些记录整理成统一口径，再进行统计。

### 3. 系统如何判断一条记录属于哪里

系统优先看资质记录里的“分公司”。

如果分公司有值，就认为这条资质属于该分公司。地图点也优先按这个分公司展示。

如果分公司缺失，系统会尝试用区域、单位、机构等信息作为地点兜底。但正常业务情况下，分公司是最关键字段。

简单理解：

```text
一条资质记录 -> 找到它的分公司 -> 归到这个分公司下面
```

### 4. 地图上的点是怎么来的

系统不会给每一条资质记录画一个点。

它会先把所有资质记录按分公司汇总：

```text
北京分公司 100 条资质记录 -> 地图上 1 个北京分公司点
上海分公司 80 条资质记录 -> 地图上 1 个上海分公司点
深圳分公司 120 条资质记录 -> 地图上 1 个深圳分公司点
```

每个分公司点会带上这个分公司的统计结果，比如：

- 持证人数
- 有效资质数量
- 30 天内到期数量
- 已过期数量
- 主要产品线
- 风险等级

### 5. 分公司显示在哪个城市

系统会根据分公司名称找到对应城市坐标。

例如：

| 分公司 | 地图显示城市 |
| --- | --- |
| 北京分公司 | 北京 |
| 上海分公司 | 上海 |
| 深圳分公司 | 深圳 |
| 武汉分公司 | 武汉 |
| 黑吉分公司 | 哈尔滨 |
| 新疆分公司 | 乌鲁木齐 |
| 海南分公司 | 海口 |

如果系统已经缓存过某个地点的坐标，会优先使用缓存坐标。

如果没有缓存，就用系统内置的分公司城市坐标。

如果还是找不到，就会兜底显示在中国区用户服务部，也就是深圳总部附近。

### 6. 大区是怎么来的

资质地图的大区不是临时计算出来的，而是系统预先维护了一张“分公司归属大区表”。

例如：

| 大区 | 包含分公司 |
| --- | --- |
| 东北大区 | 沈阳、黑吉、大连、内蒙古 |
| 华北大区 | 北京、石家庄、天津、济南、青岛、北京战略客户部 |
| 华东大区 | 武汉、杭州、上海、苏州、南京、合肥 |
| 西北大区 | 西安、兰州、新疆、太原、郑州 |
| 西南大区 | 成都、贵阳、昆明、重庆、南宁 |
| 华南大区 | 长沙、南昌、福州、广州、深圳、海南 |

系统根据分公司名称查这张表，得到大区。

如果分公司名称不在这张表里，就可能出现未匹配大区。

### 7. 资质状态怎么算

系统会拿资质有效期和当前日期比较。

判断口径：

| 有效期情况 | 系统状态 |
| --- | --- |
| 已经早于今天 | 已过期 |
| 未来 30 天内到期 | 30天内到期 |
| 未来 31-60 天内到期 | 60天内到期 |
| 未来 61-90 天内到期 | 90天内到期 |
| 超过 90 天以后到期 | 有效 |
| 日期看不懂 | 未识别 |

业务上，以下状态算“当前仍有效”：

- 有效
- 30天内到期
- 60天内到期
- 90天内到期

以下状态不算当前有效：

- 已过期
- 未识别

### 8. 总览指标怎么来

导入并筛选后，页面上方的指标这样计算：

| 指标 | 业务解释 |
| --- | --- |
| 有效资质总数 | 当前筛选范围内，还没过期且能识别的资质数量 |
| 即将到期资质 | 当前筛选范围内，30 天内到期的资质数量 |
| 已过期资质 | 当前筛选范围内，已经过期的资质数量 |
| 覆盖分公司数 | 当前筛选范围内，有资质记录的分公司数量 |
| 持证人数 | 当前筛选范围内，按人员、分公司、单位去重后的人员数 |

### 9. 分公司风险等级怎么判断

每个分公司都会有一个风险等级。

判断方式比较直白：

| 条件 | 风险等级 |
| --- | --- |
| 有已过期资质 | 高风险 |
| 或 30 天内到期资质数量较多 | 高风险 |
| 有 30 天或 60 天内到期资质 | 关注 |
| 没有明显到期风险 | 正常 |

地图点颜色就来自这个风险等级：

| 风险等级 | 地图含义 |
| --- | --- |
| 正常 | 当前资质风险较低 |
| 关注 | 有资质即将到期，需要留意 |
| 高风险 | 已有过期资质或短期到期压力较大 |

### 10. 右侧排行和图表怎么来

资质地图会展示几类分析：

| 模块 | 业务含义 |
| --- | --- |
| 分公司有效资质 TOP | 哪些分公司的有效资质最多 |
| 资质风险 TOP | 哪些分公司的过期和即将到期问题更突出 |
| 产品线资质分布 | 哪些产品线的有效资质最多 |
| 资质类型分布 | 哪些资质类型数量最多 |
| 到期趋势 | 30 天、60 天、90 天和已过期资质分别有多少 |

这些分析都基于当前筛选条件。

也就是说，用户筛选了某个大区、产品线或资质类型后，地图、指标、排行和图表都会跟着变。

### 11. 用户点击地图点会看到什么

点击某个分公司点，会打开该分公司的资质详情。

详情里可以看到：

- 该分公司的持证人数
- 有效资质数量
- 即将到期数量
- 已过期数量
- 该分公司下的资质明细
- 产品线分布
- 资质类型分布
- 到期分布

用户还可以在详情里按人员姓名和资质状态继续过滤。

### 12. 导出逻辑

用户可以导出：

- 当前筛选结果
- 某个分公司的资质详情

导出的内容就是当前页面口径下的明细数据。

## 二、中国区培训覆盖地图

### 1. 这个控件解决什么问题

这个控件用来回答：

- 全国培训主要集中在哪些培训中心？
- 哪些分公司参与培训更多？
- 哪些产线培训覆盖更高？
- 培训合格率怎么样？
- 哪些分公司或培训中心存在培训质量风险？

地图上的每一个点，代表一个培训中心。

### 2. 用户需要导入什么

用户导入培训记录表。表里通常包含：

- 分公司或区域
- 大区
- 产线
- 培训年度
- 培训月份
- 培训结果
- 培训地点
- 培训中心或举办地点
- 培训组织方
- 培训类型
- 培训名称
- 学员姓名
- 学员组织
- 讲师
- 成绩
- 班次 ID

系统会把这些培训记录整理成统一口径后进行统计。

### 3. 系统如何判断一条培训记录发生在哪里

培训地图会先找培训地点。

查找顺序是：

```text
培训地点
-> 培训中心或举办地点
-> 培训组织方
-> 未知
```

例如：

| 培训地点 | 举办地点 | 培训组织方 | 系统优先使用 |
| --- | --- | --- | --- |
| 武汉培训中心 | 空 | 中国区培训组 | 武汉培训中心 |
| 空 | 北京研究院 | 中国区培训组 | 北京研究院 |
| 空 | 空 | 深圳总部 | 深圳总部 |

然后系统会根据这个地点文字，判断它应该归到哪个培训中心。

### 4. 培训中心是怎么识别出来的

系统会把培训地点文字归一成标准培训中心。

常见规则如下：

| 地点里出现 | 归到培训中心 |
| --- | --- |
| 北京研究院、北京迈瑞研究院 | 北京分公司 |
| 北京普利生 | 北京普利生 |
| 北京旭日鸿升 | 北京旭日鸿升 |
| 深圳总部、深圳光明工厂、光明 | 深圳总部 |
| 武汉培训中心、迈瑞全球培训体验中心（武汉） | 武汉培训中心 |
| 南京基地、南京迈瑞、南京培训中心 | 南京培训中心 |
| 上海长岛 | 上海长岛 |
| 长沙天地人 | 长沙天地人 |
| 西安培训中心 | 西安培训中心 |

如果地点是类似 `天津分公司培训教室`，系统会识别成 `天津分公司`。

如果地点是类似 `北京培训教室`，系统会识别成 `北京培训中心`。

如果完全识别不出来，就归为 `未知培训中心`。未知培训中心不会显示在地图上。

### 5. 地图上的点是怎么来的

系统不会给每条培训记录画一个点。

它会先把培训记录按培训中心汇总：

```text
武汉培训中心 200 条培训记录 -> 地图上 1 个武汉培训中心点
北京分公司 150 条培训记录 -> 地图上 1 个北京分公司点
深圳总部 300 条培训记录 -> 地图上 1 个深圳总部点
```

每个培训中心点会带上这个培训中心的统计结果，比如：

- 培训人次
- 培训记录数
- 培训场次
- 合格率
- 不合格人次
- 主要产线
- 主要培训类型

### 6. 培训中心显示在哪个城市

系统会根据培训中心识别结果找到城市坐标。

例如：

| 培训中心 | 地图显示城市 |
| --- | --- |
| 北京分公司 | 北京 |
| 北京普利生 | 北京 |
| 北京旭日鸿升 | 北京 |
| 深圳总部 | 深圳 |
| 武汉培训中心 | 武汉 |
| 南京培训中心 | 南京 |
| 西安培训中心 | 西安 |
| 上海长岛 | 上海 |
| 长沙天地人 | 长沙 |

如果培训中心是某个分公司，比如 `天津分公司`，系统会用该分公司的城市坐标。

如果多个培训中心在同一个城市，系统会把点轻微错开，避免完全重叠。

例如北京可能同时有：

- 北京分公司
- 北京培训中心
- 北京普利生
- 北京旭日鸿升

它们都会在北京附近，但不会压在同一个点上。

### 7. 培训大区是怎么来的

培训地图的大区有两种来源。

第一优先级：Excel 里的大区字段。

如果 Excel 中已经有大区，并且不是 `中国区`，系统直接使用 Excel 的大区。

第二优先级：按分公司匹配系统维护的大区表。

例如：

| 分公司 | 大区 |
| --- | --- |
| 北京分公司 | 华北大区 |
| 哈尔滨分公司 | 东北大区 |
| 上海分公司 | 华东大区 |
| 武汉分公司 | 华中大区 |
| 深圳分公司 | 华南大区 |
| 成都分公司 | 西南大区 |
| 西安分公司 | 西北大区 |

系统还会处理一些别名：

| Excel 中的名称 | 系统标准名称 |
| --- | --- |
| 内蒙古分公司 | 呼和浩特分公司 |
| 新疆分公司 | 乌鲁木齐分公司 |
| 海南分公司 | 海口分公司 |
| 黑吉分公司 | 哈尔滨分公司 |
| 北京战略客户部 | 北京分公司 |

### 8. 培训结果怎么判断

培训结果会统一归为三类：

- 合格
- 不合格
- 未知

判断方式：

| 原始结果包含 | 系统归类 |
| --- | --- |
| 合格、通过、已通过、pass | 合格 |
| 不合格、未通过、fail、未合格 | 不合格 |
| 空值或其他看不懂的内容 | 未知 |

系统会先判断“不合格”，再判断“合格”。这是因为“不合格”里包含“合格”两个字。

### 9. 合格率怎么算

合格率只统计明确有结果的记录。

```text
合格率 = 合格记录数 /（合格记录数 + 不合格记录数）
```

未知结果不进入分母。

例如：

```text
合格 90 条
不合格 10 条
未知 20 条

合格率 = 90 / (90 + 10) = 90%
```

如果全部都是未知结果，合格率显示为 `暂无`。

### 10. 培训人次和培训场次怎么算

培训人次：

系统会尽量按学员去重。

去重时主要看：

```text
学员姓名 + 分公司 + 学员组织
```

也就是说，同一个人在同一分公司、同一组织下出现多次，只算一个培训人次。

如果所有记录都没有学员姓名，系统会退化为按记录数统计。

培训场次：

系统优先看班次 ID。

如果没有班次 ID，就用以下信息组合判断是不是同一场培训：

```text
培训周期 + 培训地点 + 培训类型 + 培训名称 + 产线
```

### 11. 总览指标怎么来

导入并筛选后，页面上方的指标这样计算：

| 指标 | 业务解释 |
| --- | --- |
| 培训人次 | 当前筛选范围内，按学员去重后的培训参与人数 |
| 培训记录数 | 当前筛选范围内的培训明细记录数量 |
| 培训场次 | 当前筛选范围内，按班次去重后的培训场次数 |
| 合格率 | 合格数除以有效结果数 |
| 不合格人次 | 当前筛选范围内，不合格记录数量 |

### 12. 右侧排行和图表怎么来

培训覆盖地图会展示几类分析：

| 模块 | 业务含义 |
| --- | --- |
| 分公司 TOP | 哪些分公司的培训记录更多 |
| 风险 TOP | 哪些分公司的不合格数量更多、合格率更低 |
| 产线分布 | 哪些产线培训记录最多 |
| 培训类型分布 | 哪些培训类型开展最多 |
| 培训趋势 | 各培训周期的记录数、人次和合格率变化 |

这些分析都基于当前筛选条件。

用户筛选大区、分公司、产线、培训周期、培训结果、培训中心或培训类型后，地图和统计都会同步变化。

### 13. 地图点颜色怎么来

培训地图可以切换展示模式。

#### 培训人次模式

| 条件 | 地图含义 |
| --- | --- |
| 培训人次 >= 120 | 覆盖较高 |
| 培训人次 60-119 | 中等覆盖 |
| 培训人次 < 60 | 覆盖较低 |

#### 培训场次模式

| 条件 | 地图含义 |
| --- | --- |
| 培训场次 >= 20 | 场次较多 |
| 培训场次 8-19 | 场次中等 |
| 培训场次 < 8 | 场次较少 |

#### 合格率模式

| 条件 | 地图含义 |
| --- | --- |
| 没有有效成绩 | 暂无结果 |
| 合格率 >= 90% | 效果较好 |
| 合格率 70%-89.9% | 需要关注 |
| 合格率 < 70% | 风险较高 |

### 14. 用户点击地图点会看到什么

点击某个培训中心点，会打开该培训中心的培训详情。

详情里可以看到：

- 培训人次
- 培训记录数
- 培训场次
- 合格率
- 不合格人次
- 培训明细
- 产线分布
- 培训类型分布
- 培训趋势

用户还可以在详情里按学员姓名和培训结果继续过滤。

### 15. 导出逻辑

用户可以导出：

- 当前筛选结果
- 某个分公司或培训中心的培训明细

导出的内容就是当前页面口径下的明细数据。

## 三、两个控件的关键差异

| 对比项 | 人员服务资质地图 | 培训覆盖地图 |
| --- | --- | --- |
| 地图点代表 | 分公司 | 培训中心 |
| 主要业务问题 | 服务资质覆盖和到期风险 | 培训覆盖和培训效果 |
| 地点优先字段 | 分公司 | 培训地点、培训中心、培训组织方 |
| 大区来源 | 系统维护的分公司归属表 | Excel 大区优先，其次系统维护表 |
| 颜色含义 | 资质风险等级 | 当前展示模式下的人次、场次或合格率 |
| 风险关注点 | 过期、即将到期 | 不合格数、合格率低 |
| 详情对象 | 分公司资质详情 | 分公司或培训中心培训详情 |

## 四、业务人员可以怎样理解

人员服务资质地图可以理解为：

```text
把每条资质归到分公司
-> 看每个分公司有多少有效资质
-> 看哪些资质快过期或已过期
-> 在地图上按分公司展示风险
```

培训覆盖地图可以理解为：

```text
把每条培训记录归到培训中心
-> 看每个培训中心承接了多少培训
-> 看培训参与人数、场次和合格率
-> 在地图上按培训中心展示覆盖和效果
```

如果地图上某个点位置不对，通常是地点名称没有匹配到预期城市，或者历史坐标缓存中保存了错误坐标。

如果某个点没有出现，优先检查：

- 资质地图：记录里是否有有效分公司，分公司是否被过滤。
- 培训地图：培训地点是否能识别为培训中心，是否被归为 `未知培训中心`。
