# 培训发展管理地图地点渲染与本地配置逻辑

本文档按两个地图控件分为两部分，重点说明“地图上渲染的地点是如何被找出来的”，以及大区、分公司坐标、培训中心识别、坐标缓存等本地配置文件如何参与计算。

两个控件都不是直接把 Excel 里的地点文字丢给地图展示，而是先把业务记录清洗成标准字段，再决定地图点的“业务地点名”，最后把地点名转换为经纬度，交给高德地图 `AMap.Marker` 渲染。

## 第一部分：中国区人员服务资质地图

### 1. 地图点代表什么

中国区人员服务资质地图的地图点代表“分公司”。它不是每一条资质记录一个点，也不是每个人员一个点。

完整链路是：

```text
Excel 资质记录
-> 解析出分公司、区域、单位、机构等字段
-> 生成每条记录的 geoLocationName
-> 按 branch 分公司聚合为 branchStats
-> 每个分公司生成 1 个 mapPoint
-> mapPoint 解析出 coords
-> QualificationAmap.vue 用 coords 渲染 AMap.Marker
```

涉及文件：

| 作用 | 文件 |
| --- | --- |
| Excel 字段解析、生成 `geoLocationName` | `frontend/src/utils/qualificationParser.js` |
| 分公司聚合、生成 `mapPoints` | `frontend/src/utils/qualificationAggregator.js` |
| 资质大区配置、分公司坐标配置 | `frontend/src/utils/branchGeoMap.js` |
| 坐标缓存、坐标兜底、同坐标偏移 | `frontend/src/services/geoCacheService.js` |
| 地图点和大区图层渲染 | `frontend/src/components/QualificationAmap.vue` |
| 后端坐标缓存和高德地理编码 | `backend/geo_cache_service.py` |

### 2. 每条资质记录的地点名如何找出

资质解析时，每条有效记录都会生成一个 `geoLocationName`。逻辑在 `qualificationParser.js` 的 `resolveQualificationGeoLocationName`。

候选字段顺序是：

```text
分公司 branch
-> 原始区域 region
-> 单位 organization
-> 机构 institution
-> 中国区用户服务部
```

也就是说，第一优先级永远是 Excel 里解析出来的分公司。只有分公司为空，才会用区域、单位、机构兜底。

示例：

| 分公司 | 区域 | 单位 | 机构 | 最终 `geoLocationName` |
| --- | --- | --- | --- | --- |
| 北京分公司 | 华北大区 | A 经销商 | 空 | 北京分公司 |
| 空 | 华北大区 | A 经销商 | 空 | 华北大区 |
| 空 | 空 | A 经销商 | 空 | A 经销商 |
| 空 | 空 | 空 | 深圳机构 | 深圳机构 |
| 空 | 空 | 空 | 空 | 中国区用户服务部 |

注意：资质地图后续会按分公司聚合，所以即使某个分公司下多条记录有不同的 `geoLocationName`，真正生成分公司地图点时只取该分公司聚合记录中的第一条 `geoLocationName`。

### 3. 哪些资质记录不会进入地点匹配

资质解析时会先过滤掉部分记录。以下记录不会进入后续地图点计算：

1. 空行。
2. 分公司、产品线、机器型号、资质类型、有效期全部为空的行。
3. 分公司等于 `法国`、`荷兰`、`英国`、`总部` 的行。
4. 分公司包含 `长春分公司` 的行。
5. 分公司名称包含英文字母的行。

这意味着某些 Excel 行如果因为分公司命名不符合规则被过滤，后面不会产生坐标，也不会显示在地图和统计中。

### 4. 导入时坐标缓存如何建立

页面导入成功后，`ServiceQualificationMap.vue` 会把所有记录的地点名传给坐标服务：

```text
payload.records.map(record => record.geoLocationName || record.branch)
-> normalizeLocationList 去空、去重
-> batchResolveGeo(..., { allowGeocode: true })
-> /api/geo-cache/batch-resolve
```

坐标缓存服务的处理顺序：

1. 先查内存和 `config/geo_cache.json`。
2. 再查后端内置默认坐标 `DEFAULT_COORDINATES`。
3. 如果地点名命中总部关键词，则归到深圳总部坐标。
4. 如果允许高德解析，并且配置了高德 Key，则调用高德地理编码。
5. 如果仍然失败，则兜底到深圳总部坐标。

总部关键词在 `backend/geo_cache_service.py`：

```text
中国区用户服务部
用户服务部
中国区总部
用服总部
技术支持中心
中国区
总部
```

高德地理编码 Key 支持以下环境变量：

```text
TSEP_AMAP_GEOCODE_KEY
AMAP_GEOCODE_KEY
AMAP_API_KEY
```

### 5. 分公司地图点如何生成坐标

聚合入口是 `buildQualificationDashboard`。它先按 `branch` 分组，生成 `branchStats`，再调用 `buildQualificationMapPoint`。

单个资质地图点的坐标优先级：

```text
1. geoMap 缓存坐标：resolveGeoFromMap(geoMap, item.geoLocationName || item.branch)
2. 本地分公司坐标：resolveBranchGeo(item.branch)
3. 总部兜底坐标：geoInfoToPoint(null)
```

坐标优先级展开说明：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 导入时解析出的 `geoMap` | 按 `geoLocationName` 查缓存，缓存可能来自 `config/geo_cache.json`、后端默认坐标、高德解析或总部兜底 |
| 2 | `branchGeoMap.js` 的 `BRANCH_GEO_MAP` / `CITY_ALIAS_MAP` | 如果缓存没命中，尝试用分公司名称找本地固定坐标 |
| 3 | 深圳总部坐标 | 如果前两步都失败，使用 `[114.0579, 22.5431]` |

当前实现里，坐标解析失败不会导致点消失，而是尽量归到总部坐标。

### 8. 资质城市兜底配置：`CITY_ALIAS_MAP`

如果 `BRANCH_GEO_MAP` 没有精确命中，`resolveBranchGeo` 会做一次城市兜底。

处理步骤：

1. 去掉中文括号内容：`（.*?）`。
2. 去掉 `分公司`、`战略客户部`、`总部`。
3. 看剩余文本是否包含 `CITY_ALIAS_MAP` 中的城市名。
4. 命中则返回该城市坐标。

例如：

| 输入分公司 | 标准化后 | 命中城市 | 结果 |
| --- | --- | --- | --- |
| 北京分公司二部 | 北京二部 | 北京 | 北京坐标 |
| 深圳总部培训组 | 深圳培训组 | 深圳 | 深圳坐标 |
| 苏州分公司（东区） | 苏州 | 苏州 | 苏州坐标 |

当前城市兜底包含：北京、上海、广州、深圳、成都、武汉、杭州、南京、西安、重庆、沈阳、济南、郑州、长沙、南昌、福州、厦门、昆明、贵阳、南宁、乌鲁木齐、兰州、银川、西宁、呼和浩特、哈尔滨、长春、无锡、南通、宁波、温州、东莞、佛山、洛阳、徐州。

注意：城市兜底只影响坐标，不会补全大区。大区仍然只来自 `BRANCH_REGION_MAP` 的精确分公司映射。

### 9. 资质大区图层如何渲染

`QualificationAmap.vue` 使用 `getQualificationRegionGroups()` 读取 `QUALIFICATION_REGION_GROUPS`，然后为每个大区创建 `AMap.DistrictLayer.Province`。

图层参数：

| 参数 | 来源 |
| --- | --- |
| `adcode` | 大区配置里的 `adcodes` |
| `fill` | 大区被选中或未筛选时用 `region.fill`，未选中时用浅灰透明色 |
| `province-stroke` | 大区被选中或未筛选时用 `region.color`，未选中时用浅灰描边 |
| `city-stroke` | 固定半透明白色 |
| `county-stroke` | 固定更浅的半透明白色 |

图例中的数量不是分公司配置总数，而是当前 `mapPoints` 里每个点的 `region` 统计数量。

### 10. 资质地图 marker 如何渲染

资质地图初始化：

```text
中心点：[104.195397, 35.86166]
缩放：4.5
地图样式：amap://styles/dark
```

每个 `mapPoint` 生成一个 `AMap.Marker`：

```text
position = point.coords
content = 20px 自定义 button
anchor = center
zIndex = 200
```

marker 颜色来自风险等级：

| 风险等级 | CSS tone |
| --- | --- |
| 高风险 | `critical` |
| 关注 | `warning` |
| 正常或其他 | `good` |

鼠标悬停或点击时打开信息窗，信息窗显示：

```text
分公司
所属大区
有效资质数
持证人数
30天内到期
已过期
主要产品线
风险等级
```

## 第二部分：中国区培训覆盖地图

### 1. 地图点代表什么

中国区培训覆盖地图的地图点代表“培训中心”。它不是分公司点，也不是每一场课一个点。

完整链路是：

```text
Excel 培训记录
-> 解析出培训地点、培训中心、培训组织方等字段
-> 根据地点文本归一出 trainingCenter / trainingCenterCity
-> 生成每条记录的 geoLocationName
-> 按 trainingCenter 培训中心聚合为 centerStats
-> 每个培训中心生成 1 个 mapPoint
-> mapPoint 解析出 coords
-> TrainingCoverageAmap.vue 用 coords 渲染 AMap.Marker
```

涉及文件：

| 作用 | 文件 |
| --- | --- |
| Excel 字段解析、生成培训中心和 `geoLocationName` | `frontend/src/utils/trainingParser.js` |
| 培训中心聚合、生成 `mapPoints` | `frontend/src/utils/trainingAggregator.js` |
| 培训大区配置和分公司别名 | `frontend/src/utils/branchRegionMap.js` |
| 培训中心识别、培训中心坐标和同城偏移 | `frontend/src/utils/trainingCenterMap.js` |
| 培训分公司坐标兜底 | `frontend/src/utils/trainingGeoMap.js` |
| 坐标缓存、坐标兜底、同坐标偏移 | `frontend/src/services/geoCacheService.js` |
| 地图点和大区图层渲染 | `frontend/src/components/TrainingCoverageAmap.vue` |
| 后端坐标缓存和高德地理编码 | `backend/geo_cache_service.py` |

### 2. 每条培训记录的原始地点如何找出

培训解析时先得到一个 `location`，它用于识别培训中心。

候选字段顺序是：

```text
培训地点 trainingPlace
-> 培训中心/举办地点 trainingCenterField
-> 培训组织方 organizer
-> 未知
```

示例：

| 培训地点 | 培训中心/举办地点 | 培训组织方 | 用于识别培训中心的 `location` |
| --- | --- | --- | --- |

| 空 | 北京迈瑞研究院 | 中国区培训组 | 北京迈瑞研究院 |
| 空 | 空 | 深圳总部 | 深圳总部 |
| 空 | 空 | 空 | 未知 |

### 3. 培训中心如何从地点文本中识别出来

培训中心识别逻辑在 `trainingCenterMap.js` 的 `resolveTrainingCenter(locationValue)`。

第一步会标准化地点文本：

```text
去掉所有空白字符
中文括号（ ）统一为英文括号 ( )
trim
```

识别顺序如下。

#### 3.1 精确关键词规则：`EXACT_RULES`

只要地点文本包含对应关键词，就归到配置好的培训中心和城市。

| 命中关键词 | 归一培训中心 | 城市 |
| --- | --- | --- |
| 北京迈瑞研究院、北京研究院 | 北京分公司 | 北京 |
| 北京普利生 | 北京普利生 | 北京 |

### 7. 培训分公司名称归一：`BRANCH_ALIASES`

| --- | --- |

| 北京战略客户部 | 北京分公司 |

归一函数 `normalizeTrainingBranchName(value)` 的顺序：

1. 原始值为空，返回空。
2. 如果原始值已经是标准分公司，直接返回。
3. 如果命中 `BRANCH_ALIASES`，返回别名对应的标准分公司。
4. 遍历所有标准分公司，如果原始值包含完整分公司名，或包含去掉 `分公司` 的短名，则返回该标准分公司。
5. 如果包含 `北京战略客户部`，返回 `北京分公司`。
6. 仍未命中，返回原始值。

`resolveTrainingRegion(value)` 再根据标准分公司查大区。查不到则返回 `未匹配大区`。

### 11. 培训地图点如何生成坐标

聚合入口是 `buildTrainingDashboard`。它先按 `trainingCenter` 分组，生成 `centerStats`，再调用 `buildTrainingMapPoint`。

单个培训地图点的坐标优先级：

```text
1. geoMap 缓存坐标：resolveGeoFromMap(geoMap, item.geoLocationName || item.trainingCenter)
2. 本地培训中心坐标：resolveTrainingCenterGeo(item.trainingCenter, item.trainingCenterCity)
3. 总部兜底坐标：geoInfoToPoint(null)
```

坐标优先级展开说明：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 导入时解析出的 `geoMap` | 按培训中心聚合后的第一条 `geoLocationName` 查缓存 |
| 2 | `trainingCenterMap.js` | 根据培训中心和城市使用本地中心坐标、分公司坐标、同城偏移 |
| 3 | 深圳总部坐标 | 如果前两步都失败，使用 `[114.0579, 22.5431]` |

注意：`未知培训中心` 在生成 `centerStats` 时已经被过滤，所以不会进入 `buildTrainingMapPoint`。

### 14. 两个地图共用的坐标缓存文件

两个地图都会使用 `config/geo_cache.json`。这个文件保存已经解析过的地点坐标，结构大致是：

```json
{
  "北京分公司": {
    "city": "北京",
    "lng": 116.407526,
    "lat": 39.90403,
    "source": "manual",
    "updated_at": "2026-07-08 10:30:00"
  }
}
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `city` | 坐标所属城市 |
| `lng` | 经度 |
| `lat` | 纬度 |
| `source` | 来源，常见为 `manual`、`amap`、`fallback` |
| `updated_at` | 写入或更新时间 |

如果要手工修正某个地点显示位置，可以优先改 `config/geo_cache.json` 中对应地点名的坐标。下次加载或导入时会优先命中缓存。

### 15. 两个地图共用的同坐标偏移

即使坐标解析成功，也可能多个点落在同一经纬度。两个地图都会调用 `applyPointOffsets(points)`。

处理逻辑：

1. 按经纬度保留 6 位小数生成 key。
2. 同一个 key 下如果只有 1 个点，不偏移。
3. 如果有多个点，按圆周分布做偏移。
4. 偏移半径最大控制在 `0.35`。

所以地图上看到的点有时不是原始坐标，而是为了避免重叠后的视觉偏移坐标。原始坐标会保存在 `originalCoords`。

| 培训中心关键词识别 | `trainingCenterMap.js` 的 `EXACT_RULES` |
| 培训中心城市前缀识别 | `trainingCenterMap.js` 的 `CITY_PREFIX_RULES` |
| 培训中心城市坐标 | `trainingCenterMap.js` 的 `CITY_COORDS` |
| 培训中心同城偏移 | `trainingCenterMap.js` 的 `CENTER_COORD_OFFSETS` 和 `CENTER_ORDER` |
| 培训分公司坐标兜底 | `trainingGeoMap.js` 的 `TRAINING_BRANCH_GEO_MAP` |
| 已解析地点缓存 | `config/geo_cache.json` |
| 后端默认坐标和总部关键词 | `backend/geo_cache_service.py` |

## 最容易混淆的点

1. 资质地图点是分公司点；培训地图点是培训中心点。
2. 资质地图大区只按本地分公司配置精确映射；培训地图优先使用 Excel 大区字段。
3. 资质地图如果分公司名称不在大区配置中，大区可能为空；但坐标仍可能通过城市兜底找到。
4. 培训地图如果识别成 `未知培训中心`，不会生成地图点。
5. 坐标缓存优先级高于本地固定坐标。如果缓存里的坐标错了，地图仍会优先使用缓存。
6. 坐标解析失败当前会兜底到深圳总部，不会直接隐藏点。
7. 同一坐标的多个点会被视觉偏移，地图上的点位可能略偏离原始经纬度。
